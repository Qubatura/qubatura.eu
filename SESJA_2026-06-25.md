### Q-PONG — easter egg (`pong.js`, nowe pliki HTML/CSS)

Gra zbudowana w pięciu iteracjach (v1–v5) na podstawie rosnącej specyfikacji.

#### Mechanika gry
- **Gra do 3 punktów.** Po każdym golu: flash wyniku, piłka resetuje się do centrum z krótką pauzą (~55 klatek). **Paletka gracza nigdy nie resetuje się** — zostaje tam, gdzie gracz ją zostawił.
- **Gracz:** lewa paletka. Sterowanie: mysz pionowo lub W/S/↑/↓.
- **Bot:** prawa paletka, AI `AI_SPD = 2.8`, śledzi piłkę z opóźnieniem — można go pokonać.
- **Proporcje pola 4:3** (Atari-style). `GH` dynamiczne (okno minus topbar i strefa sygnetu). Pole ok. 15% większe niż strefa sygnetu (signet skurczony do 0.62 podczas gry).
- `navFX.pageScale = 0.62` — sygnet zostaje w tle, ale mniejszy (symboliczna obecność, nie ukryty).

#### Styl wizualny — twardy 8-bit monochromatyczny
- **Jeden kolor:** biały (`rgba(255,255,255,1)`) dla wszystkiego — ściany, paletki, piłka, linia środkowa, tablica.
- **Zero glow, zero szkła, zero antyaliasingu** — płaskie `fillRect` bez `shadowBlur`.
- **Piłka:** biały kwadrat (`fillRect`), jak w oryginale z 1972.
- **Wyjątek:** flash wyniku po punkcie → kolor primary `#5B2EFF`.
- **Ściany** (góra/dół): białe, 2px. **Linia środkowa:** przerywana, `rgba(255,255,255,0.27)`.
- **EST. 1972** watermark: lewy-dolny róg, 8px Press Start 2P, `rgba(255,255,255,0.22)`.

#### Font Press Start 2P
Załadowany przez Google Fonts (dołączony do głównego `<link>`). Użyty wszędzie w obrębie gry:
- **Q-PONG** (HTML `#pong-header`): 11px, `rgba(255,255,255,0.55)`
- **Wynik** (canvas): `Math.max(16, Math.round(GH * 0.075))` px
- **Instrukcja** (HTML `#pong-footer`): 8px, `rgba(255,255,255,0.55)`
- **EST. 1972** (canvas): 8px, `rgba(255,255,255,0.22)`

#### Sterowanie — input mode (fix krytyczny)
Problem: mysz ciągnęła paletkę do centrum przy sterowaniu klawiaturą. Rozwiązanie: **eksplicytne tryby wejścia** (`inputMode: 'idle' | 'mouse' | 'key'`):
- Ruch myszy → `inputMode = 'mouse'` (tylko gdy `Date.now() - lastKeyMs >= KEY_PRIO = 600ms`)
- Naciśnięcie klawisza → `inputMode = 'key'`
- `idle`: paletka stoi nieruchomo (nigdy nie ciągnie się do `mouseY = GH/2`)

#### Przyciski prędkości (SLOW / MED / FAST)
- Pionowy stack `#pong-speed` po prawej stronie pola (pozycjonowany JS: `GL + GW + 18px`).
- Press Start 2P, 7px, monochromatyczny styl z aktywnym `.active`.
- `SLOW = 0.7x / MED = 1.0x (domyślne) / FAST = 1.4x` mnożnik `BALL_SPD`.
- **Klik zmienia prędkość natychmiast** (rescaluje `vx, vy` bieżącej piłki przez `targetSpd / curSpd`).
- Ważne: speed panel setup jest PO definicji `state`, żeby handler closure miał dostęp do `state.ball`.

#### Przycisk pauzy
- `<button id="pong-pause">PAUSE</button>` wewnątrz `#pong-speed`, oddzielony `.speed-sep`.
- Toggle `paused = !paused` → `if (paused) return;` w pętli RAF (canvas zamrożony, pętla nadal żyje).
- Tekst zmienia się na `PLAY` gdy pauza aktywna, `.active` class.
- `#pong-speed` ma `width: 64px` — stała szerokość kontenera, żeby zmiana PAUSE↔PLAY nie powodowała skakania pozostałych przycisków.

#### Finałowa karta — cytat + postać historyczna
Po zdobyciu 3 punktów:
1. **Fade out pola** (canvas, header, footer, speed panel) — 0.6s.
2. **Fade in cytatu** — 0.8s, wyśrodkowany, Chakra Petch 300, `clamp(12px, 1.3vw, 16px)`.
3. **Fade in imienia + dat** — 0.6s, delay +0.55s od cytatu (staggered). Chakra Petch 600, `clamp(17px, 2.1vw, 26px)`, uppercase, glow `#5B2EFF`.
4. **Wszystko wyśrodkowane** — `align-items: center`, `text-align: center` na całej karcie.
5. **Wspólny fade out** po ~4s → overlay znika → sygnet wraca do skali 1.0.
6. Karta ma **świadomy kontrast stylistyczny z grą** — jest to Chakra Petch, elegancko, w stylu marki; celowo inna od 8-bitowej gry.
